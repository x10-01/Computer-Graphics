# 2026-11-06 课堂记录：Shader 类封装与外部文件加载

> 本记录对应课堂投影中
> `RenderObject(Shader &shader, GLuint vao)`、`shader.UseProgram()` 以及
> `Shader shader = Shader("res/shaders/core.vs", "res/shaders/core.fs")`
> 的版本。代码细节同时与本次上传的 `main.cpp`、`shader.h` 核对。

## 1. 本节内容在课程中的位置

此前（9.18、10.9）使用的流程，是在 `main.cpp` 中以字符串保存 Vertex
Shader 和 Fragment Shader 源码，再通过 `CreateShaderProgram()`
完成创建、编译、附加和链接。

11 月 6 日课堂版本把这部分封装进 `Shader` 类，并将 Shader
源码放在独立文件中：

-   `shader.h`：定义 `Shader` 类。
-   `res/shaders/core.vs`：Vertex Shader 文件。
-   `res/shaders/core.fs`：Fragment Shader 文件。
-   `main.cpp`：创建 Shader 对象，并在绘制时调用对象方法。

这是对原先 Shader Program 管理方式的结构调整；不是取消 Vertex
Shader、Fragment Shader 或 Program 的概念。

## 2. Shader 类的组成

本次上传的 `shader.h` 中，类名为 `Shader`，包含以下公开接口：

  --------------------------------------------------------------------------------------------------
  成员                                                         作用（按当前源码）
  ------------------------------------------------------------ -------------------------------------
  `Shader(const char* vertexPath, const char* fragmentPath)`   构造函数；创建
                                                               Program，分别编译两个文件中的
                                                               Shader，最后链接 Program

  `~Shader()`                                                  析构函数；调用
                                                               `glDeleteProgram(shaderProgram)`

  `UseProgram()`                                               调用
                                                               `glUseProgram(shaderProgram)`，使该
                                                               Program 用于后续绘制
  --------------------------------------------------------------------------------------------------

私有成员：

-   `GLuint shaderProgram`：保存 Shader Program 对象编号。
-   `CompileShaderFromFile(const char* path, GLenum type)`：读取、编译并附加指定
    Shader。
-   `LinkShaderProgram()`：链接 Program，并检查链接状态；Windows
    条件编译分支中还进行 Program 验证。

## 3. `CompileShaderFromFile()` 的执行顺序

当前 `shader.h` 中的流程如下：

1.  创建 `std::string code`，用于保存 Shader 文件内容。
2.  创建 `std::ifstream shaderFile`。
3.  设置文件流异常标志：`failbit | badbit`。
4.  在 `try` 中通过 `shaderFile.open(path)` 打开文件。
5.  创建 `std::stringstream shaderStream`，通过
    `shaderStream << shaderFile.rdbuf()` 读取文件内容。
6.  关闭文件，并把流内容赋给 `code`。
7.  通过 `code.c_str()` 得到 Shader 源码指针。
8.  调用 `glCreateShader(type)` 创建对应类型的 Shader 对象。
9.  调用 `glShaderSource()` 提交源码。
10. 调用 `glCompileShader()` 编译。
11. 通过 `glGetShaderiv(shader, GL_COMPILE_STATUS, &success)`
    查询编译状态。
12. 编译失败时，通过 `glGetShaderInfoLog()` 获取日志、输出错误信息并
    `exit(-1)`。
13. 编译成功后，调用 `glAttachShader(shaderProgram, shader)` 将 Shader
    附加到 Program。
14. 调用 `glDeleteShader(shader)` 删除该 Shader 对象。

### 必须区分的对象

-   `shader`：单个 Vertex Shader 或 Fragment Shader 对象。
-   `shaderProgram`：将相应 Shader 附加并链接后供绘制使用的 Program
    对象。

因此，Shader 编译错误使用 `glGetShaderInfoLog()`；Program 链接错误使用
`glGetProgramInfoLog()`。

## 4. `LinkShaderProgram()` 的执行顺序

当前上传源码中可见：

1.  `glLinkProgram(shaderProgram)`。
2.  `glGetProgramiv(shaderProgram, GL_LINK_STATUS, &success)`。
3.  如果失败，调用 `glGetProgramInfoLog()` 输出链接日志，并终止程序。
4.  在 `#ifdef __WIN64` 条件下，调用
    `glValidateProgram(shaderProgram)`。
5.  查询 `GL_VALIDATE_STATUS`；失败时读取 Program 日志并终止程序。

## 5. `main.cpp` 中的调用变化

### 5.1 Shader 对象创建

当前上传的 `main.cpp` 在 GLEW 初始化成功、`CreateVertexBuffer()`
执行之后、Render Loop 之前创建对象：

``` cpp
Shader shader = Shader("res/shaders/core.vs", "res/shaders/core.fs");
```

两个参数分别是 Vertex Shader 与 Fragment Shader 的文件路径。

### 5.2 `RenderObject()` 的函数签名变化

11 月 6 日课堂投影及当前上传源码对应：

``` cpp
static void RenderObject(Shader &shader, GLuint &vao)
```

函数内部的关键调用顺序：

1.  `shader.UseProgram()`：启用 Shader 类内部保存的 Program。
2.  `glBindVertexArray(vao)`：绑定对应 VAO。
3.  `glDrawArrays(GL_TRIANGLES, 0, 3)`：按三角形图元绘制 3 个顶点。
4.  `glBindVertexArray(0)`：解除 VAO 绑定。

此前版本的 `glUseProgram(shaderProgram)` 已由 `shader.UseProgram()`
这一封装调用替代。当前文件中仍保留一行被注释的旧调用，它不是当前执行路径。

### 5.3 Render Loop 的整体位置关系

``` text
glfwInit
  ↓
设置 OpenGL 3.3 Core Profile
  ↓
glfwCreateWindow
  ↓
glfwMakeContextCurrent
  ↓
glewInit
  ↓
CreateVertexBuffer
  ↓
创建 Shader 对象（读取 core.vs / core.fs，编译并链接）
  ↓
while Render Loop
  ├─ SetViewport
  ├─ glClearColor
  ├─ glClear
  ├─ RenderObject(shader, VAO)
  ├─ glfwSwapBuffers
  └─ glfwPollEvents
  ↓
glfwTerminate
```

Shader 的创建和编译链接不应放进每帧循环；绘制时才调用 `UseProgram()`。

文件移动到项目根目录，也不需要把路径改成绝对路径。**

## 8. 当前源码中需要记住、但不能擅自修改的风险点

以下是对本次上传文件的审查，不是老师明确要求修改的内容：

1.  **文件读取失败后的流程：** `catch` 输出 `ERROR::FILE_NOT_READ`
    后，当前函数仍继续创建并编译
    Shader；如果文件确实未读到，后续可能再出现 Shader 编译失败。
2.  **重复链接：** `LinkShaderProgram()` 当前有两次 `glLinkProgram()`
    和两次链接状态检查，需要对照老师完整原文件确认。
3.  **析构时机：** 当前 `main.cpp` 在 `glfwTerminate()` 之前没有显式结束
    `Shader` 对象作用域，而 `Shader` 析构函数会调用
    `glDeleteProgram()`。按当前 C++ 局部对象生命周期，析构发生在
    `main()` 退出时，晚于显式执行的 `glfwTerminate()`。这可能导致删除
    Program 时不再有有效的 OpenGL
    Context。不要自行改变老师代码；后续如需修正，先核对课堂示例或向老师确认。
4.  **头文件依赖：** 当前 `shader.h` 使用 GLEW 类型、`std::cout` 和
    `exit()`，但头文件自身没有完整包含所有对应头文件。当前 `main.cpp`
    先包含 GLEW、`iostream`，再包含
    `shader.h`。这说明本项目依赖当前包含顺序；本次作业不要擅自重构。
