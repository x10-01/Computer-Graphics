## 1. 必须修正：PATH 环境变量宏

原笔记出现：

``` text
PATH=$PATH$;..\Dll
```

本次 Visual Studio 调试属性截图中实际显示：

``` text
PATH=$(PATH);..\Dll
```

因此原笔记应更正为 **`$(PATH);..\Dll`**。

解释：

-   `$(PATH)`：Visual Studio 属性表达式中的 PATH 环境变量宏，用于保留原
    PATH。
-   `;`：Windows PATH 条目分隔符。
-   `..\Dll`：相对于当前项目目录返回上一级，再进入 Dll 文件夹。

调试属性截图同时显示工作目录为：

``` text
$(ProjectDir)
```

这与 Shader 文件使用 `res/shaders/...` 相对路径的方式相关。

## 4. Lib 文件夹

截图确认存在：

``` text
Lib/
├── glew32.lib
├── glew32s.lib
├── glfw3.lib
├── glfw3_mt.lib
└── glfw3dll.lib
```

Visual Studio → 链接器 → 常规 → 附加库目录：

``` text
..\Lib
```

Visual Studio → 链接器 → 输入 → 附加依赖项截图显示：

``` text
opengl32.lib;glew32.lib;glfw3.lib;%(AdditionalDependencies)
```

**重要：**
目录中存在多个库文件，不代表本项目同时链接了所有文件。当前截图确认实际附加依赖项是
`opengl32.lib`、`glew32.lib`、`glfw3.lib`，没有显示
`glew32s.lib`、`glfw3_mt.lib` 或 `glfw3dll.lib`
被选中。不要擅自替换库变体。

## 7. 对原笔记中"避免空格和中文路径"的修订

原笔记建议路径尽量避免空格、中文和特殊字符。当前实际项目路径包含
`Computer Graphics` 空格，截图中的相对路径配置仍然可以成立。

因此建议把原表述改为：

> 项目路径尽量保持简单、稳定，减少不必要的特殊字符；但路径包含空格并不必然导致失败。应优先核对
> Visual Studio
> 属性中的相对路径、工作目录和实际目录层级，不要仅凭路径包含空格就判断为错误。
