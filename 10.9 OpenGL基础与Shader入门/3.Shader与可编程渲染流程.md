# 3. Shader 与可编程渲染流程

## 3.1 Shader 是什么

Shader（着色器）是运行在 GPU
图形渲染流程中的程序，用于规定图形数据在相应渲染阶段如何处理。

本节主要接触两类 Shader：

-   **Vertex Shader：** 处理输入的每个顶点，输出顶点位置等数据。
-   **Fragment Shader：** 处理光栅化阶段产生的片段，输出片段颜色等信息。

## 3.2 从顶点到片段

``` text
顶点数据
   ↓
Vertex Shader（VS）
   ↓
Rasterization（光栅化）
   ↓
Fragment Shader（FS）
   ↓
后续逐片段处理与颜色缓冲区
```

黑板上的流程图强调了 VS、Rasterization 与 FS
的先后关系。顶点经过顶点着色阶段处理后，图形装配与光栅化阶段会根据图元生成覆盖区域中的片段，再交给
Fragment Shader 处理。

本节绘制的是一个三角形，因此输入是三个顶点；这并不意味着输出只会有三个片段。光栅化会根据三角形在窗口中的覆盖范围产生许多片段。

## 3.3 CPU、GPU 与顶点输入

当前程序先在 C++ 代码中定义顶点数组，再通过 VBO 将数据交给 OpenGL
管理，并使用 VAO 记录如何读取这些数据。

因此，当前课堂采用的是**通过顶点缓冲区提供顶点属性**的路线。不要把"顶点数组在
C++ 中声明"和"GPU 如何读取顶点属性"混为一谈：

-   C++ 代码负责组织初始数据并发出 OpenGL 调用。
-   VBO 保存上传的顶点数据。
-   VAO 记录顶点属性读取配置。
-   绘制时，GPU 按配置读取顶点属性并执行 Shader。

老师提到输入数据可以通过不同方式提供；本节代码使用的是 VBO/VAO
这条路径。

## 3.4 GLSL 与 C++

C++ 是负责创建窗口、管理数据和调用 OpenGL API 的宿主程序语言。GLSL
是写在 Shader 源码中的着色器语言。

课堂把 GLSL 源码存储为 C++ 字符串：

``` cpp
const GLchar* vertexShaderSource =
"#version 330 core\n"
"layout (location = 0) in vec3 position;\n"
"void main()\n"
"{\n"
"gl_Position = vec4(position, 1.0f);\n"
"}";
```

这里的 C++ 字符串只是承载 Shader 源码。`glShaderSource()`
会把字符串提交给 OpenGL，之后由 OpenGL 的 Shader 编译流程处理。

## 3.5 为什么字符串里有 `\n`

`\n` 是 C/C++ 字符串中的换行转义符。它让提交给 Shader
编译器的源码保留清晰的行结构，有助于编译器在错误信息中指出对应行号。

## 3.6 课堂结构上的两条线

老师将当前程序从结构上分为两条线：

1.  `CreateShaderProgram()`：准备 Shader Program，属于渲染程序准备部分。
2.  `CreateVertexBuffer()`：准备顶点数据与顶点属性配置，属于顶点数据部分。

两条线都在进入 Render Loop 前完成初始化；真正绘制时通过 `RenderObject()`
将 Shader Program 与 VAO 一起使用。
