# 2. Render Loop、颜色与 Double Buffering

## 2.1 Render Loop 的作用

Render Loop 是窗口保持运行期间反复执行的循环。课堂代码的基本结构为：

``` cpp
while (!glfwWindowShouldClose(window))
{
    SetViewport(window);

    glClearColor(0.2f, 0.3f, 0.3f, 1.0f);
    glClear(GL_COLOR_BUFFER_BIT);

    RenderObject(shaderProgram, VAO);

    glfwSwapBuffers(window);
    glfwPollEvents();
}
```

循环每次迭代都执行当前帧的准备、绘制、显示和事件处理。用户关闭窗口后，循环结束，再执行
`glfwTerminate()`。

## 2.2 `glClearColor()`

``` cpp
glClearColor(0.2f, 0.3f, 0.3f, 1.0f);
```

该函数设置后续清理颜色缓冲区时使用的颜色，并不单独完成清屏。四个参数依次为
R、G、B、A。

本次课堂的背景色约为深青灰色。

## 2.3 RGBA：0--1 与 0--255

RGBA 是四个颜色通道：

-   R：Red，红色
-   G：Green，绿色
-   B：Blue，蓝色
-   A：Alpha，透明度

常见的颜色表示有两种：

1.  **8-bit 通道表示：** 每个通道通常用整数 `0–255` 表示。
2.  **归一化浮点表示：** 每个通道用 `0.0–1.0` 表示。

需要注意 API 的要求：`glClearColor()` 接收归一化浮点数，不应直接把
`0–255` 的整数当作参数传入。若已有 8-bit 通道值，应换算为：

``` text
归一化值 = 8-bit 通道值 / 255.0
```

例如，`51 / 255.0 = 0.2`，所以红色通道值 51 对应 `0.2f`。`1.0f`
对应通道最大值 255；Alpha 为 `1.0f` 表示完全不透明。

## 2.4 `glClear()`

``` cpp
glClear(GL_COLOR_BUFFER_BIT);
```

该调用清理颜色缓冲区，使用此前由 `glClearColor()` 指定的颜色填充背景。

记忆区别：

-   `glClearColor()`：指定清屏颜色。
-   `glClear()`：真正执行清理。

## 2.5 Front Buffer、Back Buffer 与双缓冲

课堂提到显示窗口中的前缓冲区（Front Buffer）和后台缓冲区（Back
Buffer）。

基本思想：

1.  在后台缓冲区准备当前帧。
2.  当前帧绘制完成后，交换前后缓冲区。
3.  让已经准备好的画面显示出来，再继续准备下一帧。

如果把每一步绘制过程直接暴露给显示端，用户可能看到尚未完成的画面。双缓冲通过先在后台准备画面、再交换显示，减少这种问题。

## 2.6 `glfwSwapBuffers()`

``` cpp
glfwSwapBuffers(window);
```

交换指定窗口的前后缓冲区，使已经准备好的后台画面成为显示画面。它与本节的双缓冲机制直接相关。

## 2.7 `glfwPollEvents()`

``` cpp
glfwPollEvents();
```

处理已经发生的窗口系统事件，例如窗口关闭、键盘和鼠标事件。它不负责绘制三角形，也不负责交换缓冲区。

## 2.8 本节顺序

``` text
设置视口
→ 设置清屏颜色
→ 清理颜色缓冲区
→ 绘制对象
→ 交换前后缓冲区
→ 处理窗口事件
```

本笔记只记录课堂已讲的双缓冲基本思想，不提前扩展 VSync
等尚未讲授的内容。
