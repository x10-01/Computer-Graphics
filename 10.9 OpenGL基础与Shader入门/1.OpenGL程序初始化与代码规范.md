# 1. OpenGL 程序初始化与代码规范

## 1.1 头文件顺序

课堂代码使用：

``` cpp
#include <GL/glew.h>
#include <GLFW/glfw3.h>
#include <iostream>
```

-   `GL/glew.h`：提供 GLEW 的声明。
-   `GLFW/glfw3.h`：提供 GLFW 窗口、上下文和事件接口。
-   `iostream`：用于 `std::cout`、`std::endl` 等标准输入输出功能。

按课堂写法，先包含 GLEW，再包含 GLFW，避免 OpenGL 头文件声明产生冲突。

## 1.2 初始化顺序

``` cpp
if (!glfwInit())
    return -1;

glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);
glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 3);
glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);

GLFWwindow* window = glfwCreateWindow(
    640, 480, "OpenGL Triangle", NULL, NULL
);

if (!window)
{
    glfwTerminate();
    return -1;
}

glfwMakeContextCurrent(window);

if (GLEW_OK != glewInit())
{
    std::cout << "GLEW init fails!" << std::endl;
    glfwTerminate();
    exit(-1);
}
```

窗口标题仅用于显示；公开笔记中的示例不保留个人标识。实际课程作业中的标题按老师要求填写。

### 为什么顺序不能随意交换？

1.  `glfwInit()`：先初始化 GLFW。
2.  `glfwWindowHint()`：创建窗口前，指定希望使用的 OpenGL 版本与
    Profile。
3.  `glfwCreateWindow()`：创建窗口，并建立与之关联的 OpenGL Context。
4.  `glfwMakeContextCurrent(window)`：将该窗口的 Context
    设置为当前上下文。
5.  `glewInit()`：在当前 OpenGL Context 建立后初始化 GLEW。
6.  完成初始化后，才执行依赖 OpenGL 函数的 VAO/VBO 和 Shader Program
    创建操作。

**课堂强调：** `glCreateProgram()` 与
`CreateShaderProgram(shaderProgram)` 应放在 GLEW 初始化成功之后、`while`
渲染循环之前。`CreateVertexBuffer()` 也在进入循环前调用。

## 1.3 OpenGL Context

OpenGL Context 是执行 OpenGL
操作所依赖的上下文环境。创建窗口不等于已经把该 Context
设置为当前上下文，因此需要调用：

``` cpp
glfwMakeContextCurrent(window);
```

之后再初始化 GLEW，并进行 Shader、VAO、VBO 等 OpenGL 操作。

## 1.4 `return -1` 与 `exit(-1)`

-   `return -1;`：结束当前函数并返回错误值。写在 `main()`
    中时，会结束程序入口函数。
-   `exit(-1);`：直接终止整个进程，不依赖当前函数是否为 `main()`。

课堂的 Shader 创建函数是独立函数，因此在不可继续的 Shader
编译或链接错误分支中使用
`exit(-1)`，可以终止整个程序。错误退出前应按当前代码处理需要清理的资源，例如调用
`glfwTerminate()`。

这两种写法不能简单理解为完全等价；应结合代码所在函数和清理需求判断。

## 1.5 `std` 命名空间规范

老师要求标准库名称尽量写完整，不使用：

``` cpp
using namespace std;
```

课堂采用：

``` cpp
std::cout << "GLEW init fails!" << std::endl;
```

这样可以明确 `cout` 和 `endl` 来自 C++
标准库，减少命名冲突，也符合老师要求的代码风格。

## 1.6 Visual Studio 逻辑视图与项目属性

本次排查中，属性窗口打不开与打开方式有关：切换到解决方案的**逻辑视图**后，才能按项目层级找到对应属性。

需要区分：

-   **文件夹视图：** 主要呈现磁盘上的目录与文件。
-   **逻辑视图：** 按 Visual Studio
    解决方案、项目、引用、头文件、源文件等逻辑组织内容。

修改第三方库路径时，应从正确的项目属性入口检查配置。相对路径是否有效，取决于路径相对于项目文件的位置以及原有目录层级是否保持一致；移动或重命名文件夹后不能只凭"使用了相对路径"就断定配置一定正确。

## 1.7 初始化顺序速记

``` text
glfwInit
→ glfwWindowHint
→ glfwCreateWindow
→ glfwMakeContextCurrent
→ glewInit
→ CreateVertexBuffer / CreateShaderProgram
→ while Render Loop
→ glfwTerminate
```

这是课堂程序的基本顺序。具体函数先后以老师当堂代码为准。
